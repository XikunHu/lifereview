# LifeReview 每日生命回顾

把一天的真实行为、身体变化和个人参照连接起来。先给读者最值得知道的判断，再用数据说明；不输出分数，不用固定模板制造异常。

## 入口与分工

- 日报、晨报、指定日期复盘由本 Skill 负责数据审计与综合解读。
- 用户要生命轨迹、时间轴或轨迹多版时，读取已安装的 `lifereview-trajectory-map-20260808`（公开包目录 `lifereview-trajectory-map`）；轨迹角色、节点门禁与文案以它为准。
- 周报由 `lifereview-weekly-20260628`（公开包目录 `lifereview-weekly`）负责；它继承本包 `references/analysis-contract.md` 的数据与推理规则。
- LifeReview 是个人复盘系统，LifeBrief 是产品。只有明确开发 LifeBrief 时才应用服务端契约、客户端渲染和发布流程。

## 每次执行

1. 确定分析日期 D 和时区；默认 Asia/Shanghai。晨报必须分别标出所用的日间活动日期、醒来日和生成时间。用户给了结构化事实底板时，先使用它，不重复索取或访问无关原始数据。
2. 先读 [分析契约](references/analysis-contract.md)。只有涉及源文件、同步延迟或数据缺口时再读 [数据管线](references/data-pipeline.md)；Looki 拉取时读 [Looki 协议](references/looki-protocol.md)；睡眠解释时读 [睡眠与恢复](references/sleep-recovery.md)。
3. 核对每源日期、单位、覆盖、来源、错误状态。缺失、零值、请求失败、主动禁用分别记录。历史文件的 mtime 不用来判定历史日期的覆盖质量。
4. 读取当天完整可用指标池，在睡眠、恢复、活动结构、步态、环境、代谢、呼吸循环中挑出解释力最强的 3–5 项。没有变化就明确平稳，不为了换主题硬凑。
5. 为每个解释性数字找到个人基线、当天对照或跨日位置；没有参照时保留事实并缩小判断。基线写明窗口、有效天数和来源，不照抄历史个人常数。
6. 对照真实行为与身体时间窗；D 日行为的睡眠结果读取 D+1，D 日文件睡眠只作为当天开始时的底子。日历只能支持安排背景，不能证明出席或训练完成。
7. 生成下面的简短报告，再按 [回归场景](references/test-cases.md) 自查适用条目。明确区分事实、个人关联、待验证假设。

## 默认输出

- **日期与一句话判断**：最值得关注的变化及其实际意义，证据不足时说清能判断的范围。
- **关键解释**：2–3 条，每条连接数字、个人参照与真实行为/时间关系；不编造生理机制或后果。
- **当天轨迹**：只在用户要求或确有新增信息时调用轨迹 Skill；不用流水账填充。
- **下一步**：0–2 个具体动作，回答什么时候、做什么、用什么结果复核。涉及日程只引用本次读到的真实安排；不替用户改日历。
- **数据审计**：每源一行紧凑列出实际覆盖或失败；与判断无关的缺口不塞进正文。

每段短，标题具体。指标最多两三项一组。`HRV` 保留原名；`RHR` 写静息心率，`CV` 写血糖波动，`REM` 写快速眼动睡眠。正文不出现内部字段、证据等级和取证话术。

## 取数与脚本边界

- 优先使用用户已提供的底板、已验证的 canonical/DB，再按需要读取源文件。现有本地脚本在 LifeReview 中心目录 `scripts/`；历史 `~/.life-log/tmp/` 可为兼容软链，调用前检查真实路径和参数。
- 公开仓库的脚本与本机生产管线可能不同。先检查脚本是否存在以及是否写库、发消息、调用模型；不能把脚本名称当成能力证明。
- `health-extract.py` 会更新 canonical，`daily-brief-ad.py` 主流程会调用模型并发送消息；检查 Skill 不运行这些生产入口。`--no-looki` 只禁用 Looki，不能当作预览或禁止发送开关。
- freshness 工具存在时可辅助检查实时同步；不存在时按数据内部时间戳与预期区间审计，不能因此阻塞历史复盘。
- 不硬编码推送群、Bot、调度时间或任务 ID。需要投递时读取当前配置，并遵循用户这次明确授权；普通复盘只回复当前会话。
- 不默认创建飞书文档、修改自动任务、补写健康 DB、请求额外凭据或发送消息。

## 保留的分析能力

指标聚合、碎步/步态、训练证据、日照、心率与活动的关联、awake_to_work_gap 和视角池见 [指标与视角](references/metrics-and-lenses.md)。这些是分析工具，不是固定必报项。

CGM 规则、睡眠夜晚归属、HRV 均值和采样口径、佩戴门控均在分析契约中。周报使用同一文件，避免维护第二套旧规则。

旧五格式与旧评分示例可从Git历史 `80f82d3:skills/lifereview-daily/SKILL.md` 查阅，不作为现行提示词加载。用户明确要求旧风格时可以借用结构，仍遵守本版数据与推理规则。
