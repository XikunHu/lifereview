# LifeReview 生命轨迹

> 技术 ID：`lifereview-trajectory-map-20260808`
> 用户名称：**LifeReview 生命轨迹**
> v2.1.0（2026-08-09）：把禁词修补升级为证据分层、行为×身体双门禁与时间窗约束；收紧日历、全天指标和睡眠基线规则。

## 核心目标

让用户一眼看懂：**我做了什么 → 身体哪项数据变了 → 相对我自己的平常水平算高还是低。**

不是罗列指标，不是解释方法论，不是声明"无法确认原因"。

## 五条硬规则（v2.1，违反即重写）

### 1. 行为与身体必须同时过门禁

- 每个轨迹节点必须同时具备：`真实行为锚点` + `同一时间窗内值得说的身体回应`。只有行为、只有身体，或两者时间窗不兼容，都不做节点。
- 合法行为证据：已发生的 Looki 行为、训练或活动记录、步行等设备可核对行为、入睡/起床边界。睡眠边界是已发生的状态转换，可作为行为锚点。
- 日历只代表计划线索，不代表已经执行；只有其他记录能佐证发生时，才可升级为行为锚点。与睡眠等事实冲突时必须排除。
- 无行为的生理节点在轨迹列表中上限为 **0**；有行为但没有身体回应的日历项也不补位。合格节点不足 4 个时就少写。
- 轨迹节点数是门禁后的结果，不是需要凑满的目标。

### 2. 指标时间窗必须与节点兼容

- 小时指标只能挂到该小时内已确认的行为；没有行为证据时，转为跨时段洞察或删除。
- 全天指标只能放在“全天步行/全天活动”等同尺度的真实行为节点或底部洞察，禁止硬挂到 17:00、20:00 等单个事件。
- 只有日期、没有具体时刻的自动识别活动，写 `时段未提供`；不得根据相邻心率、起床时间或日历空档猜测发生时段。
- 同一节点若同时使用多项指标，它们必须共享可解释的聚合窗口；小时值、单点值、全天值不得混称为同一时段回应。

### 3. 解释性数字必须带坐标

用于支持判断的健康/行为指标至少满足一种：

- 个人基线：`HRV 64 ms · 高于 7 天均值 59`
- 当天对比：`步数峰值 2,223 · 其他时段不到 400`
- 跨天位置：`日照 122 分钟 · 一周最多`

日期、时间戳、起止时间和纯结构性时长不需要额外比较，禁止为满足规则制造机械坐标。睡眠总时长、深睡、HRV、静息心率只要展示，就必须有个人基线方向；若事实底板没有个人睡眠基线，睡眠总时长与睡眠结构只能做明确的前后夜对比，不能冒充 7 天基线。

### 4. 每句话必须有增量信息

写完自检：删掉这句，用户是否损失信息？不损失就删。

### 5. 时长必须写出来

`15:00–18:00 · 3 小时`、`20:00–22:00 · 2 小时`。不许只说"最长的连续安排"。

## 永久禁用表达

写了等于没写，一律禁止：

- 没有构成已识别的高点
- 为当时状态提供了参照
- 只能确认同时发生，暂不判断原因
- 现有证据不能确认原因
- 附近记录只能提供背景
- 覆盖了当天多个关键时段
- 身体信号在不止一个时段出现
- 恢复要结合两项一起看
- 深睡与 REM 都有记录

**术语（永久）**：

- HRV 旧别名全线废止，一律写 `HRV`；不做首次括注，不做后续简称。
- `CV` → `血糖波动 4%（越低越平稳）`
- `RHR` → `静息心率`
- `REM` → `快速眼动睡眠`
- 不显示：frag_index、phys_type、evidence_tier、运动佐证、原因未确认、同窗

## 因果边界的新写法

不写面向用户的方法论免责声明，只陈述证据窗口内可读的事实或可能性：

| 情况 | 写法 |
|---|---|
| 心率高 + 有活动记录 | `身体活动更频繁` |
| 心率高 + 接近常见餐时 | `身体活动更频繁，也可能和进食有关` |
| 心率高 + 无任何记录 | `这段没有对应记录` |
| 训练 + 心率同步升高 | `训练把心率推到全天最高` |
| 活动多但心率平 | `活动不少，心率没跟着上去` |

其余边界不变：日历空白只代表没有安排；低步数只代表少移动；无进餐记录不命名餐后反应；单点 HRV 高值写"单次高值"；无 Looki 不编造行为。

## 维度多样性配额

同一指标族在轨迹节点主体内**最多出现 2 次**；第二次必须形成峰值、回落或前后对照。底部洞察可以跨族引用，但不能复述节点原句。心率不得因覆盖率高而成为默认指标。

| 族 | 字段 | 何时值得写 |
|---|---|---|
| 睡眠结构 | 总时长/深睡/快速眼动/入睡起床 | 每天（起床节点） |
| 恢复 | HRV、静息心率、夜间心率 | 每天，必带基线 |
| 心率负荷 | 逐时均值/峰值、运动心率 | 有行为对应时 |
| 活动结构 | 步数、峰值步数、集中度、活动能量、锻炼分钟 | 有峰值或结构变化 |
| 步态质量 | 步速、步长、不对称、双支撑 | 超出个人常态才写 |
| 环境暴露 | 日照分钟、环境声 | 明显偏离才写 |
| 代谢 | 血糖均值/范围/波动 | 有餐时或明显波动 |
| 呼吸循环 | 呼吸率、血氧 | 明显偏离才写 |

生成前先问：今天哪 3–4 个族真的动了？只写动了的。

## 节点格式

```text
09:00｜🏃 力量训练 · 1 小时
心率 100–142 · 步数 1,414
全天最强的一小时，心率比均值高 36。
```

- 第一行：时间 + 图标 + 行为 + 时长（同一行，行为名占整行宽度以减少换行）
- 第二行：指标最多 2 项，确有必要才 3 项
- 第三行：一句人话，必须带坐标
- 单行尽量不超过 20–25 个汉字，能两行就不写三行

## 两句洞察

固定两句，来自**不同族**。每句必须含：具体数字 + 方向词（高于/低于/最多/最少/唯一）+ 跨时段或跨指标关系。

自检：这句话换到任何一天还成立吗？成立就是废话。

好例子：

```text
两个洞察
1. 日照 122 分钟是过去一周的四倍以上，步态不对称降到 0.2%，这是最近走得最舒展的一天。
2. 睡了 7.5 小时、HRV 回到 64，静息心率却是一周最高的 55；恢复和心脏负荷这次没有同向。
```

坏例子：

- 今天整体状态不错。（无数据）
- HRV 下降说明压力大。（单日过度因果）
- 建议早睡多运动。（不是洞察）
- 行为与身体读数覆盖了多个时段。（换哪天都成立）

## 视角池

生成多版时，每版换一个真问题：

1. 基线偏离：今天哪几项脱离了我的均值
2. 结论优先：主矛盾是什么
3. 矛盾信号：恢复变好但另一项变差
4. 活动结构：总步数由什么组成、峰值在哪
5. 环境暴露：日照/声音是否解释了这一天
6. 步态质量：走路本身有没有变化
7. 代谢曲线：血糖变化落在哪个行为时段
8. 日程密度：事情最多时身体是否最紧
9. 训练余波：训练后多久回落
10. 起点与结果：前夜底子与次日睡眠
11. 低活动对比：不动是否等于休息
12. 睡眠结构：总量内部如何分配

无信号的视角不用：步态只有超出个人常态才讲；单次正念不独立成视角；正常血氧不为丰富度硬塞。

## 睡眠归属

D 日文件中的睡眠是开始 D 日时的底子；评价 D 日行为之后的睡眠必须读 D+1。

## DeepSeek V4 Flash 运行策略

仅当用 `deepseek-v4-flash` 批量生成时遵循：

- 不要在一个请求里生成 10 版，该模型可能把额度耗在 thinking 上导致正文为空。
- 每个视角单独请求，成功即存独立文件。
- 首次 `max_tokens=16000`；只有 thinking 无正文时单条重试 `24000–32000`。
- 并发 2–3，设超时；中断后只续跑缺失版本。
- 参考脚本：`scripts/run_deepseek_resumable.py`。
- 日常生产只生成信号最强的 1 版；多版仅用于探索和评测。

## 质量检查

- [ ] 每个节点同时有真实行为锚点与同窗身体回应
- [ ] 日历计划没有被自动写成已发生行为
- [ ] 无行为生理节点为 0；无身体回应的行为节点也为 0
- [ ] 小时、单点、全天指标没有跨时间窗硬挂
- [ ] 睡眠/深睡/HRV/静息心率都带个人基线方向；无个人睡眠基线时明确写前后夜对比
- [ ] 所有解释性数字都有坐标，结构性时间没有机械比较
- [ ] 连续时段写了起止和时长
- [ ] 同一指标族在节点主体 ≤ 2 次，第二次承担对比作用
- [ ] 禁用表达和 HRV 旧别名零命中
- [ ] 恰好两句洞察，来自不同族，换天不成立
- [ ] 没有编造行为、时间或基线，没有把共现写成确定因果
- [ ] 多版之间是不同问题，不是换标题
