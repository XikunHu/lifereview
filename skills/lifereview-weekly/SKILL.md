# LifeReview 每周生命回顾

让读者看懂这一周发生了什么变化，哪些安排值得保留或调整。按证据决定重点，不强行覆盖每个维度。

## 依赖与执行

1. 确定连续7个完整分析日和时区。用户指定自然周就使用那一周；否则使用最近7个已结束日期，并在报告开头写起止日期。
2. **先读取日报包的 `references/analysis-contract.md`**：公开仓库相对路径 `../lifereview-daily/references/analysis-contract.md`；Proma 日期目录安装路径 `../lifereview-daily-20260701/references/analysis-contract.md`。选择真实存在的那个。依赖缺失时提示补齐完整日报包；不能声称已按现行契约完成健康关联分析。
3. 优先读已提供的事实底板或 canonical/DB，按7天逐日检查日期、单位、来源和覆盖。仅在必要时回读原始文件，不以每个历史文件今天的 mtime 判过期。
4. D 日行为与 D+1 日睡眠配对；周末日行为的睡眠结果可能在周外，缺少就留空。按醒来日统计的一周睡眠与按行为日配对的结果必须区分。
5. 周统计只纳入该指标的有效日。每个周均值写 n/7，缺失不补零；少于3个有效日只列可用事实，不称周趋势。步数、能量等同时显示有效日总量与有效日均值，不把缺失日当低活动日。
6. 优先用前一个可比7日或用户的个人基线比较，写明覆盖、来源和算法；来源/窗口改变时分段，不能把设备切换写成身体突变。
7. 分析日历结构与实际行为的关系。重叠时段去重，工作、生活、交通安排分开；安排不能冒充已执行行为。无 Looki 时不补刷手机、饮食、小憩或主观状态。
8. 新规律只作为个人关联或待验证假设，并给出样本量与替代解释；不把7天模式升级成因果定律。

## 默认输出

1. **一句话判断**：本周最值得知道的趋势或矛盾；没有稳定信号就写平稳/资料有限，不强制红黄绿。
2. **为什么**：2–4条，每条有观察数字、可比参照和行为/时间关系。不能仅凭另一个指标正常就排除某病因或断言“结构出了问题”。
3. **下周行动**：0–3个有证据支持的具体实验，写触发条件、动作和复核指标；不强制分别填训练、饮食、工作。
4. **本周趋势与参考表**：只把关键趋势展开，其余可靠指标放表。保留7天日期列、缺失标记、有效n和基线/前周；数据少时允许精简表。
5. **数据审计**：逐源说明实际覆盖、失败/缺失和哪些判断因此未做。CGM按逐日full/partial/fragment分层；partial可分析局部，不纳入全天状态对应。
6. **可选深挖**：本周有价值的新视角、训练后观察或逐日轨迹；使用轨迹时另读轨迹Skill，不为篇幅凑齐。

## 周报专用检查

- HRV 先使用同口径的每夜均值，再按有效夜求周均；写SDNN/窗口/样本覆盖。不能在前文要求中位数、后文又要求均值。
- 夜间分布前低后高时附具体读数和采样数，不称“假恢复”，不自动剔除；可比较原始与过滤后的敏感性。
- 睡眠、训练及日照的跨日配对正确；无次夜数据就不评价当日行为结果。
- 全周缺CGM就省去血糖关联正文，在审计说明一次；局部覆盖的日只讨论已覆盖时段。
- 完成训练与推测活动段分别统计，不用日历训练或步数阈值认定运动完成。
- 行为信号矩阵只在有明确行为且帮助解释趋势时提供；缺记录记缺失，不能记零。
- 不照抄某个人的固定深睡、HRV、静息心率或训练目标；个人基线从本次证据读取。

## 工具与副作用

没有可假定存在的 `weekly-review.py` 完整生成器；不要运行不存在的入口。可以直接根据已核验底板生成周报；需要脚本时先检查中心目录中实际文件和副作用。

仅阅读/生成周报不创建飞书文档、不向群发送消息、不修改自动任务、不回写数据库。需要外发时遵循用户本次明确指定的目标与已有授权。日报的当前运行配置从实际配置读取，本Skill不保存旧群、旧Bot、旧任务时间。
